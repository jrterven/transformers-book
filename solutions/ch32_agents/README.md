# Chapter 32 | Worked solutions

Use the [exercise sheet](../../examples/ch32_agents/EXERCISES.md) and the
[recorded episodes](../../examples/ch32_agents/records/) to check the tool sequences.

1. **Trace a changed room.** Catalog lookup returns `E-CAM` and the pointer `N-17`, leaving five calls. Reading `N-17` leaves four calls. In the active case it supplies `R-MAPLE` and 875 cents per guest. The room lookup reports 16 spaces and leaves three calls. The quote returns 10,700 cents and leaves two. In the cancellation case the second response supplies the cancellation and the model next returns an answer. There are still four calls available when it stops.
2. **Check arguments and evidence.** Both the string and the extra key fail the dispatcher schema. With a valid integer rate of 800 and fee of 200, the calculator gives $12(800)+200=9{,}800$ cents. Inspect the published notice to see that the rate had changed to 875 cents.
3. **Calculate an exact price.** Multiply seven guests by 675 cents to get 4,725 cents. Add 250 cents once to get 4,975 cents, or 49.75 dollars. Adding the fee for each guest charges six extra fees, or 1,500 cents more.
4. **Budget a conversation.** The lengths are 960, 1,140, 1,320, 1,500 and 1,680 tokens. They add to $5(960)+180(0+1+2+3+4)=6{,}600$. The fifth call exceeds the input cap by 80 tokens.
5. **Design a workflow baseline.** Look up the extracted title. Ask if two records match. Resolve any notice and stop on cancellation. Check whether the current room is open and its capacity is at least the group size. Then compute the quote. To compare both systems on the same sentences, add an extraction stage and score its title and group size, including missing or ambiguous inputs.
6. **Make one instruction more precise.** In `MEASURED_RUN.json` the model asks about the morning and evening options, but its evidence array is empty. In `CLARIFICATION_RUN.json` it includes `E-SK1` and `E-SK2`. A program can join either ID to a catalog record, retain both candidates, and wait for a choice. A held-out case could use two pottery sessions with different IDs and the same shortened title.
7. **Report a truncated run.** In `BUDGET_RUN.json` the catalog and notice execute. The model proposes looking up `R-MAPLE`. The application still needs the room's availability and capacity. One possible reply is “The latest notice moves Camera Lab to the Maple Room. I still need to verify the room for your group before confirming a price.”
8. **Check reliability across runs.** The probability of three failures is $(1-0.7)^3=0.027$, so at least one success has probability 0.973. Three successes have probability $0.7^3=0.343$. A shared catalog outage can make the trials fail together.
9. **Plan a handoff.** Supply the confirmed event and room, both records with dates, and the question about the accessible entrance for that session. In delegation the lead calls a specialist and chooses what to do with the returned evidence. In a handoff the specialist receives control, resolves the conflict, and issues the next tool request or answer.
10. **Verify effects after a timeout.** Record the intended workshop, guest count, operation ID, and last observed status. Query by operation ID for a reservation or a receipt. A fixture can apply the write and then drop the response. Retry with the same supported idempotency key and assert that one record, with the matching event and guest count, exists before reporting success.
11. **Recover a waiting task.** Retain the user's request, `E-CAM`, `N-17`, the pending status, wake time, deadline and counters. The unguarded continuation reads `R-OAK`, which the published notice supersedes. Read the released notice, verify `R-MAPLE` and then compute the quote from the current rate. This order earns the evidence check in the guarded trace.
12. **Separate elapsed time from the measured horizon.** Set $q=0.9$. Inverting the curve gives $h=60\sqrt{1/q-1}=60\sqrt{1/9}=20$ minutes of human reference time. The actual run takes $20+90+15=125$ minutes. A benchmark using the chapter's task-completion horizon reports the human reference time at the chosen success threshold.
13. **Design a measurement.** Hold each question fixed and compare its active versus cancelled record. Add held-out paraphrases of each. Score the correct disposition, amount and current room, then require access to the evidence in causal order. Report model turns and end-to-end elapsed time, including stops. A larger sample of ordinary requests can estimate how often each failure occurs during everyday use.
